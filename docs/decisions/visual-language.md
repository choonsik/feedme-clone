# 시각 언어: 아이소매트릭

## Decisions

- 화면의 시각 언어는 아이소매트릭 블록으로 통일합니다. 카드, 버튼, 선택 칩, 안내 상자는 위쪽 면에 오른쪽 옆면과 아래쪽 옆면이 붙은 직각 블록이고, 두 옆면은 30° 기울기로 그립니다. 모서리를 둥글게 하거나 흐린 그림자로 입체감을 내지 않습니다.
- 블록은 역할별 면 색 세트(위, 오른쪽, 아래)를 씁니다. 기본은 흰색 계열, 주요 동작은 인디고, 선택됨은 민트, 오류는 붉은 계열, 안내는 하늘색입니다. 면 색은 `ui-composition`의 의미 토큰 위에 얹는 별도 토큰 묶음으로 두고, 화면마다 임의의 색을 만들지 않습니다.
- 바닥은 30° 격자 무늬 위에 블록이 놓인 모양입니다. 라이트와 다크 두 테마 모두 같은 구조의 면 색 묶음을 갖습니다.
- 버튼은 누르면 블록이 눌려 들어가고 옆면이 얇아집니다.
- 입력창은 블록이 아니라 안쪽으로 파인 면으로 표현합니다.
- 글자 그림자(오른쪽 아래 방향으로 겹친 단단한 그림자)는 URL 입력창의 입력 텍스트에만 씁니다. 그 밖의 글자는 평평하게 둡니다.
- 일러스트는 같은 기울기의 블록과 점선 화살표로 그립니다.

## Boundaries

- `ui-composition`을 대체하지 않습니다. 공통 shell, 상태 설계, 좁은 화면 규칙, 같은 역할은 같은 variant라는 원칙은 그대로 적용합니다. 이 결정은 그 위에서 컴포넌트의 겉모습만 정합니다.
- 블록 질감은 shadcn 컴포넌트를 그대로 쓰는 것만으로는 만들 수 없으므로, 공식 컴포넌트 위에 공통 variant로 입히는 방식을 씁니다. 화면마다 따로 구현하지 않습니다.
- 긴 본문, 코드, 표처럼 읽는 글에는 장식을 넣지 않습니다.

## Why

사용자가 서비스의 첫인상으로 아이소매트릭 스타일을 직접 골랐고, 입력창 글자에만 그림자를 넣는 것까지 확정했습니다. 입체 블록은 "페이지가 변환되어 LLM으로 넘어간다"는 흐름을 일러스트로 보여 주는 데에도 맞습니다. 글자 그림자를 입력창에만 둔 것은 화면 전체에 넣었을 때 사용자가 의도보다 과하다고 판단했기 때문입니다.

## Reconsider when

- 이 스타일이 좁은 화면이나 접근성(대비, 포커스 표시)을 반복해서 해친다는 근거가 나올 때
- 같은 프로젝트에 이 시각 언어로 표현되지 않는 새 화면 유형이 생길 때

## Still-rejected alternatives

- shadcn 기본 모양(평평한 둥근 카드)을 그대로 쓰는 방식 — 일관성과 구현 비용은 낮지만, 사용자가 고른 시각 정체성을 담지 못합니다.
- 글자 그림자를 제목, 버튼, 라벨까지 전체에 쓰는 방식 — 입체감은 커지지만 사용자가 입력창만 원했고, 작은 글자에서는 번져 보입니다.
